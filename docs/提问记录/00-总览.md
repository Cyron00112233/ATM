## 三个反复出现的薄弱点

```
① "机制细节"容易混
     · 会话超时：刷新 vs 标记
     · 两个 50：手续费封顶 vs 明细上限
     · 卡状态 vs 会话状态
     · addPathPatterns vs excludePathPatterns
     · useGeneratedKeys = 回填 id（不是控制自增）
     · void vs Future<void>

② "为什么要这么设计"答不深
     · JWT 无状态 = 无法撤回
     · 用户枚举攻击的风险
     · secret 泄露 = 伪造身份（不是"登录账号"）

③ 看漏关键信息
     · 只看了 addPathPatterns，没看 excludePathPatterns
     · 只看属性名猜意思，没看注释
     · 知道 API 不同（parse vs tryParse），说不清后果
```

## 一个反复出现的"毛病"（比知识点更重要）

```
每一轮的错误，几乎都有同一个特征：【看到一半就下结论】。

对照：AI 自己也犯过同样的错
  · Get-ChildItem 漏 -Recurse → 误判"没配 SDK"
  · 没展开 $USER_HOME$ → 误判"28 个包缺失"
  · 没做 URL 解码 → 又误判
  · 出题时说"界面上也看不出来" → 严格说能看到，只是容易被忽略

结论：读代码 / 排查问题的硬功夫是
    把【所有相关的行、所有相关的证据】都看完，再下结论。
```

## 学习路线

```
第 1 阶段  问答 —— 建立整体认识            ✅ 完成（四轮 36 题）
第 2 阶段  读懂代码 —— 逐行解析 + 专业写法   ✅ 完成（五~七轮 30 题）
第 3 阶段  从需求到代码 —— 练"写"的能力     ⏸️ 暂缓（目标改为"能读"）
第 4 阶段  找 bug 练习 —— 检验是否真懂       🔄 进行中（第八轮 5 题）
```

**能力验证结果：**

```
✅ 能读懂代码    前七轮 66 题证明
✅ 能发现错误    第八轮 5 题抓到 4 题
✅ 能说清后果    不是"感觉不对"，而是"会导致 X"
```

**第 4 阶段还可以继续的：**

```
⬜ 边界类 bug（超时判断的等于边界、limit 传 0 / 负数）
⬜ 误判测试（给一段【正确】的代码，看会不会误报）
⬜ 数据一致性 bug（并发下流水余额不准）
```

**其他可选项：**
