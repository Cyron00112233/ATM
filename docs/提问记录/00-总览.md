## 三个反复出现的薄弱点

```
① "机制细节"容易混
     · 会话超时：刷新 vs 标记
     · 两个 50：手续费封顶 vs 明细上限
     · 卡状态 vs 会话状态
     · addPathPatterns vs excludePathPatterns
     · useGeneratedKeys = 回填 id（不是控制自增）

② "为什么要这么设计"答不深
     · JWT 无状态 = 无法撤回
     · 用户枚举攻击的风险
     · secret 泄露 = 伪造身份（不是"登录账号"）

③ 三种错误阶段分不清（编译期 / 启动期 / 运行期）
     · 第一次问（第五轮）答错
     · 第二次问（第六轮）答对 ✅
```

---

## 一个反复出现的"毛病"（比知识点更重要）

```
每一轮的错误，几乎都有同一个特征：【看到一半就下结论】。

例子：
  · 拦截器白名单 → 只看 addPathPatterns，没看 excludePathPatterns
  · 两个 50       → 把"手续费封顶"和"明细上限"当成一个
  · useGeneratedKeys → 猜成"控制自增"，没看注释里写的"取回来"
  · 编译期/运行期 → 只想到"会报错"，没分清哪个阶段

对照：AI 自己也犯过同样的错
  · Get-ChildItem 漏 -Recurse → 误判"没配 SDK"
  · 没展开 $USER_HOME$ → 误判"28 个包缺失"

结论：读代码 / 排查问题的硬功夫是
    把【所有相关的行、所有相关的证据】都看完，再下结论。
```
