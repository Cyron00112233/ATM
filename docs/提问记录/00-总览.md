## 知识掌握地图

**最后更新：2026-10-29**

### 一、认证与安全

| 知识点 | 状态 |
|---|---|
| 两套认证机制的区别（JWT vs 会话 token） | ✅ 第一轮 |
| BCrypt vs MD5（随机盐、彩虹表、故意慢） | ✅ 第三轮 |
| `verified` 双阶段校验 | ✅ 第三轮 |
| 卡状态机（1 正常 / 2 锁定 / 3 挂失 / 4 注销） | ✅ 第三轮 |
| **JWT payload 是 Base64 不是加密 → 只放非敏感信息** | ✅ 第四轮 |
| **`sessionToken` = UUID 去横线（32 位），和 `session_no` 是两个东西** | ⚠️ 第四轮 |
| **用户枚举攻击（登录失败提示统一）** | ⚠️ 第四轮，方向对但风险说错 |
| 会话超时的两个动作（刷新 vs 标记） | ⚠️ 第三轮 |
| 退卡是"改状态"不是"删记录" | ❌ 第三轮 |
| 全局异常处理器只拦"抛出去的异常" | ❌ 第二轮 |

### 二、事务与并发

| 知识点 | 状态 |
|---|---|
| 事务回滚的触发方式（抛异常 → 回滚） | ✅ 第一轮 |
| 条件更新 / CAS（防超扣、防超卖） | ✅ 第二轮 |
| 原子自增（防丢失更新） | ✅ 第三轮 |
| 按 `account_id` 升序更新防死锁 | ✅ 第二轮 |
| **"减少要校验够不够，增加不需要"（余额和钞箱通用）** | ⚠️ 第四轮 |
| **只读操作不需要事务** | ✅ 第四轮 |
| `@Transactional` 防"多表不一致"，不防"余额不足" | ⚠️ 需能复述 |
| `verifyPassword` 加事务 → 永远锁不了卡 | ✅ 第三轮复盘补上 |

## 三个反复出现的薄弱点

```
① "机制细节"容易混
     · 会话超时：刷新 vs 标记
     · 两个 50：手续费封顶 vs 明细上限
     · 卡状态 vs 会话状态

② "为什么要这么设计"答不深
     · JWT 无状态 = 无法撤回
     · 用户枚举攻击的风险
     · 退卡改状态不删记录

③ 前端（Dart）基础薄弱
     · 空安全、异步、命名参数
     · 已给文档：docs/Dart基础.md
```

## 第 2 阶段建议的练习顺序

```
① maskCardNo      卡号脱敏（字符串处理，最简单，已练过一次）
② validateAmount  金额校验（100 整数倍 + 范围）
③ calcFee         手续费三档（BigDecimal 四步演进）
④ generateTransNo 流水号生成
⑤ verifyPassword  密码验证（最难：BCrypt + 原子自增 + 锁卡）
```

**方法：先写伪代码（中文分步）→ 再翻译成代码 → 对照真实实现 → 看差在哪。**
