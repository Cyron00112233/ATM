## 知识掌握地图

### 一、认证与安全

| 知识点 | 状态 |
|---|---|
| 两套认证机制的区别（JWT vs 会话 token） | ✅ 第一轮 |
| BCrypt vs MD5（随机盐、彩虹表、故意慢） | ✅ 第三轮 |
| `verified` 双阶段校验 | ✅ 第三轮 |
| 卡状态机（1 正常 / 2 锁定 / 3 挂失 / 4 注销） | ✅ 第三轮 |
| **JWT 三段结构（header/payload 可解，signature 防篡改）** | ✅ 第五轮 |
| **JWT payload 只放非敏感信息** | ✅ 第五轮 |
| **secret 泄露 = 可伪造任意身份** | ⚠️ 第五轮，曾低估后果 |
| **拦截器白名单优先（`excludePathPatterns` > `addPathPatterns`）** | ❌ 第五轮，答反了（第一轮答对过） |
| 拦截器为什么自己写 JSON | ✅ 第五轮 |
| `afterCompletion` 为什么必须 clear ThreadLocal | ✅ 第五轮 |
| 会话超时的两个动作（刷新 vs 标记） | ⚠️ 第三轮 |
| 退卡是"改状态"不是"删记录" | ❌ 第三轮 |
| 全局异常处理器只拦"抛出去的异常" | ❌ 第二轮 |

## 三个反复出现的薄弱点

```
① "机制细节"容易混
     · 会话超时：刷新 vs 标记
     · 两个 50：手续费封顶 vs 明细上限
     · 卡状态 vs 会话状态
     · addPathPatterns vs excludePathPatterns

② "为什么要这么设计"答不深
     · JWT 无状态 = 无法撤回
     · 用户枚举攻击的风险
     · secret 泄露 = 伪造身份（不是"登录账号"）

③ 前端（Dart）基础薄弱
     · 空安全、异步、命名参数
     · 已给文档：docs/Dart基础.md
```

## 一个反复出现的"毛病"（比知识点更重要）

```
第五轮两处错题（JWT Q3、拦截器 Q1），和第一到四轮的所有错题，
有个共同特征：【看到一半就下结论】。

例子：
  · 拦截器 Q1   → 只看 addPathPatterns，没看 excludePathPatterns
  · 第四轮 Q4   → 把"手续费 50"和"明细上限 50"当成一个
  · 第三轮 Q5   → 知道"会出问题"，但没推完"出什么问题"

对照：我自己也犯过同样的错
  · Get-ChildItem 漏 -Recurse → 误判"没配 SDK"
  · 没展开 $USER_HOME$ → 误判"28 个包缺失"
  · 没做 URL 解码 → 又误判一次

结论：读代码 / 排查问题的硬功夫是
    把【所有相关的行/所有相关的证据】都看完，再下结论。
```
