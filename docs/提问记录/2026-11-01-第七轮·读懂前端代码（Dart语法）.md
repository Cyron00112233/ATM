# ① `const` / `final` / 普通变量

## 讲解要点

**看真实代码（`main.dart` L33-49）：**

```dart
Step step = Step.insertCard;              // 普通变量
bool loading = false;                      // 普通变量
String sessionToken = '';                  // 普通变量（空串，不是 null）
List<dynamic> detailList = [];             // 普通变量
final cardCtrl = TextEditingController();  // final
```

**三者对比：**

| | 能否重新赋值 | 值什么时候确定 | 例子 |
|---|---|---|---|
| 普通变量 | ✅ 能 | 运行时 | `Step step = Step.insertCard;` |
| `final` | ❌ 只能一次 | 运行时 | `final cardCtrl = TextEditingController();` |
| `const` | ❌ 只能一次 | **编译期** | `const SizedBox(height: 24)` |

**判断标准：**
```
值会变                     → 普通变量
值只设一次，但运行时才知道  → final
值写代码时就固定了          → const
```

**`final` 的关键细节（容易误解）：**

```dart
final cardCtrl = TextEditingController();

cardCtrl.text = '6222020000000001';    // ✅ 允许！改的是对象内部属性
cardCtrl = TextEditingController();     // ❌ 编译错误！改的是"变量指向谁"
```

**`final` 锁的是"指向哪个对象"，不是"对象内部不能改"。**

**`const` 为什么在 Flutter 里用得这么多（81 次）：**

```dart
const Text('请插入银行卡')                  // ✅ 文字固定
const SizedBox(height: 24)                  // ✅ 尺寸固定
const Text('余额：$menuBalance')            // ❌ 编译错误！menuBalance 会变
```

**好处：`const` Widget 在编译期就确定 → 界面重画时可以复用，不用重新创建。**

## 检验（3 题，全对 ✅✅✅）

**Q1**：`Step step = ...` 用哪个关键字？
**你的答案**：普通

**Q2**：`Text('余额：$menuBalance')` 能用 const 吗？为什么？
**你的答案**：用普通，不能，menuBalance 会变

**Q3**：一个页面里只创建一次、之后一直用的滚动控制器用哪个？
**你的答案**：用 final

**评分**：✅✅✅

# ② 空安全（`String` vs `String?`）

## 讲解要点

**核心规则：**

```dart
String  name = '张三';    // 不能为 null
String? name = null;      // 可以为 null
```

**看真实代码（`_call` 的返回类型）：**

```dart
Future<ApiResult?> _call(String path, Map<String, dynamic> body) async {
//           ↑ 这个问号
  if (!mounted) return null;      // ← 所以这里能返回 null
}
```

**调用方必须处理 null：**

```dart
final r = await _call(...);
if (r == null) return;        // ← 编译器强制你写
if (!r.ok) { ... }            // ← 不写上一句，这里会编译报错
```

**这就是空安全的价值：把"空指针异常"从运行期提前到编译期。**

**四种操作符：**

| 操作符 | 名字 | 作用 | 例子 |
|---|---|---|---|
| `?` | 可空类型 | 允许 null | `String? name` |
| `??` | 空值合并 | 左边是 null 就用右边 | `name ?? '默认值'` |
| `?.` | 安全访问 | 左边是 null，整个返回 null | `name?.length` |
| `!` | 非空断言 | 我保证不是 null（猜错就崩） | `name!` |

**项目里的 `??` 用法：**

```dart
sessionToken = (r.data['sessionToken'] ?? '').toString();
//               从 Map 取值，可能是 null  → 用 '' 兜底  → 转成字符串
```

## 检验（3 题，全对 ✅✅✅）

**Q1**：这三行分别用哪个关键字？答对（a 普通 / b 普通且不能 const / c final）

**Q2**：`(r.data['cardNo'] ?? '').toString()` 在干什么？
**你的答案**：取 map 里面取值，如果有值就取值，没有就取 `''`
**评分**：✅ 正确（漏了最后 `.toString()` 转字符串，小事）

**Q3**：为什么 `_call` 返回 `Future<ApiResult?>` 而不是 `Future<ApiResult>`？
**你的答案**：第一种能返回 null，第二种如果返回 null 就会报错
**评分**：✅ 正确

**精确说法**：写成 `Future<ApiResult>` 的话，`return null;` 那一行**直接编译报错**（类型不允许）。

# ③ 异步：`Future` / `async` / `await`

## 讲解要点

**看真实代码（`_call`）：**

```dart
Future<ApiResult?> _call(String path, Map<String, dynamic> body) async {
  setState(() => loading = true);          // ① 显示转圈
  final r = await apiPost(path, body);     // ② ★ 等网络
  if (!mounted) return null;               // ③ 界面还在吗
  setState(() => loading = false);         // ④ 关掉转圈
  return r;                                // ⑤ 返回结果
}
```

**三个关键字：**

| 关键字 | 一句话 |
|---|---|
| `Future<T>` | "一个还没到的 T" —— 相当于餐厅的**取餐号** |
| `async` | "这个函数里会有等待" |
| `await` | "就在这儿等着，等好了再往下" |

### ⭐ 时间线（最关键的一节）

**假设网络要 800 毫秒：**

```
时刻      发生什么
─────────────────────────────────────────────────────
T1      你按下按钮 → withdraw()
T3      setState(loading = true) → 界面显示转圈
T4      执行到 await apiPost(...)
             ★ 函数在这里【暂停】，控制权交还给 Flutter
T5      （800ms 里 Flutter 照常运行：界面能重画、按钮能点、
         用户可能点了「退卡」或关窗口！）
T6      网络响应回来
T7      await 拿到结果，_call 从暂停处【继续】执行
T8      检查 mounted（界面还在吗）
T9      setState(loading = false) → 转圈消失
T10     return r
```

**核心认知：**

> **`await` 不是"卡住整个程序"，而是"暂停这一个函数，让别的事情先跑"。**

**餐厅类比：**

```
同步    → 站在柜台前等出餐（后面的人全动不了）
异步    → 拿个取餐号回座位，叫号了再去取（await 恢复执行）
```

### 为什么有 await 就必须写 `Future<...>`

```
方法体里有 await  →  方法变成"异步方法"
                  →  返回类型必须包一层 Future
                  →  并且必须加 async
```

| 方法结束时返回什么 | 返回类型 |
|---|---|
| 什么都不返回 | **`Future<void>`** |
| 返回一个 ApiResult（可能 null） | `Future<ApiResult?>` |
| 返回一个 List | `Future<List<TransRecord>>` |

**项目里 8 个方法全是 `Future<void>`：**

```dart
Future<void> insertCard() async { ... }
Future<void> verifyPassword() async { ... }
Future<void> withdraw() async { ... }
... 共 8 个
```

### 三种常见错误

**① 忘了 `await`** —— 拿到的是 Future 对象不是结果
```dart
final r = _call(...);
print(r.ok);        // ❌ 编译错误：Future 类型没有 ok 属性
// Dart 的类型系统会当场拦住你
```

**② `await` 之后直接 setState，忘了检查 mounted**
```dart
final r = await apiPost(...);
setState(() { loading = false; });   // ❌ 界面已销毁时报错
```

**③ 在 setState 里做耗时操作** —— 阻塞渲染
```dart
setState(() { final r = await apiPost(...); });   // ❌ setState 回调不能 async
```

### 项目里"故意不 await"的一处

```dart
setState(() => step = Step.menu);
_refreshMenuBalance();      // ← 故意不 await
```

```
await 的话 → 先查余额（100ms）才切菜单 → 用户感觉卡了一下
不等的话   → 立刻切菜单，余额查完再更新数字 → 体验更好
```

**这叫「先响应，后加载」。** 但只适合"失败了也无所谓"的后台刷新。

## 检验（3 题，2✅ 1❌）

**Q1**：`await` 等网络那 800ms 里，Flutter 在干什么？
**你的答案**：别的事情能够照常跑
**评分**：✅ **完全正确**

**Q2**：为什么 `await` 之后要写 `if (!mounted) return null;`？
**你的答案**：检验当前界面换了没有，不写的话当界面换了就会崩
**评分**：✅ 正确（精确说：`mounted` = State 是否还挂在 widget 树上）

**Q3**：一个什么都不返回、又有 await 的方法，返回类型写什么？ ❌
**你的答案**：void
**正确答案**：**`Future<void>`**

**为什么：**
```
void          = 同步方法，立刻执行完，没有返回值
Future<void>  = 异步方法，结束时没有返回值
              （但"完成"这个信号本身是异步的）

规则：只要有 await，返回类型就必须包一层 Future —— 包括"不返回数据"的情况
```

**写成 `void` 的编译错误：**
```
Functions marked 'async' must have a return type assignable to Future
```

**记忆法：**
```
有 await → 方法"会晚一点完成"
        → "晚一点完成"这件事本身就是一个 Future
        → 所以哪怕不返回数据，也要写 Future<void>
```

# ④ 命名参数 + 匿名函数

## 讲解要点

**命名参数（大括号）—— Flutter 里到处都是：**

```dart
Scaffold(
  appBar: AppBar(title: Text('ATM自助服务')),    // appBar: 命名的
  body: Padding(                                 // body: 命名的
    padding: const EdgeInsets.all(24),
    child: Center(...),
  ),
)
```

**特点：用 `{}` 声明，调用时写名字，顺序无所谓。**

**`required` 标记必填：**

```dart
const MyCard({super.key, required this.title});
```

**位置参数（小括号）—— 项目里的 `_bigButton`：**

```dart
Widget _bigButton(String text, VoidCallback onTap) { ... }
_bigButton('取 款', () { ... })     // ← 靠顺序区分
```

**两种对照：**

| | 写法 | 调用 | 靠什么区分 |
|---|---|---|---|
| 位置参数 | `(String a, int b)` | `f('x', 1)` | **顺序** |
| 命名参数 | `({String a, int b})` | `f(a: 'x', b: 1)` | **名字** |

**匿名函数：**

```dart
_bigButton('取 款', () {
  amountCtrl.clear();
  setState(() => step = Step.withdraw);
})
//              ↑ () = 没有参数，{} = 函数体，没有 return
```

**`() => 表达式` 是简写（只有一行时）：**

```dart
setState(() => step = Step.withdraw);
//  等价于
setState(() { step = Step.withdraw; });
```

# ⑤ switch 表达式 / 集合推导 / 字符串插值

## switch 表达式（Dart 3 新语法）

```dart
String _title() => switch (step) {
      Step.insertCard => 'ATM自助服务',
      Step.password   => '请输入交易密码',
      ...
    };
```

**三个特点：**
```
① => 后面直接是结果，不用 return
② 编译器检查【是否覆盖所有枚举值】，漏一个就编译报错
③ 比 if-else 链清晰
```

**漏掉枚举值的报错：**
```
The type 'Step' is not exhaustively matched by the switch cases
```

## 集合推导（列表里写 for / if）

```dart
children: [
  for (final v in values)
    Expanded(child: ...),
]
```

**等价于 Java：**
```java
for (int v : values) { children.add(new Expanded(...)); }
```

**`if` 也能写在列表里：**

```dart
children: [
  if (loggedIn)
    _bigButton('返回菜单', ...)
  else
    _bigButton('重新插卡', ...),
]
```

## 字符串插值

```dart
'可用余额 $menuBalance 元'                              // 单个变量 → $变量名
'金额：${toDouble(...).toStringAsFixed(2)} 元'          // 表达式 → ${...}
```

**规则：**
```
$变量名       → 只能是一个简单变量名
${任意表达式} → 有运算、方法调用、属性访问时必须用 ${}
```

**经典错误：**
```dart
'余额：$amount * 2 元'        // ❌ 只替换 amount，" * 2 元" 当普通文字
'余额：${amount * 2} 元'      // ✅
```

## 检验（3 题，全对 ✅✅✅）

**Q1**：`_bigButton('取 款', ...)` 和 `Scaffold(appBar: ...)` 分别是什么参数方式？
**你的答案**：a 用顺序，b 用名字
**评分**：✅

**Q2**：switch 表达式漏掉一个枚举值会怎样？
**你的答案**：编译报错，编译器会查漏，不会运行时报错
**评分**：✅ **完全正确**

**Q3**：`'余额：$amount + 100 元'` 错在哪？
**你的答案**：b 是错的，有运算必须用 `${}`，而 b 没有
**评分**：✅

**先教了"读嵌套 Widget 的方法 —— 从外往里"：**

```
Row(                                    ← ① 横着排
  children: [                           ← ② 里面装一排
    for (final v in values)             ← ③ 对每个数字
      Expanded(                         ← ④ 平均分宽度
        child: Padding(                 ← ⑤ 加点空隙
          child: OutlinedButton(        ← ⑥ 描边按钮
            onPressed: () => amountCtrl.text = '$v',
            child: Text('$v'),
          ),
        ),
      ),
  ],
)
```

**三步读法：**
```
第 1 步：看最外层的容器（Row / Column / Scaffold）→ 决定整体布局方向
第 2 步：看 child / children 里有几个东西 → 决定数量
第 3 步：逐个看每个子 Widget 的参数 → 决定细节
```
